# 项目知识库维护协议

## 推荐结构

使用一个主 Markdown 文件，包含项目概览、来源索引、事实库、洞察与假设、决策日志、视觉资产规则、待验证项和版本日志。附件保留原文件。

## 来源字段

记录 source_id、名称/路径、类型、内容日期、收录日期、提供者、用途、可信度和状态。网页需记录 URL 与访问日期；PPT/PDF保留页码；表格保留工作表与单元格范围；图片记录区域；访谈区分原话与总结。

## 原子知识模板

```text
[KB-ID] 内容
类型：事实/偏好/洞察/假设/决策/约束
来源：source_id + 具体位置
置信度：高/中/低
适用范围：品牌/产品线/SKU/渠道/地区
有效期：长期/阶段/截至日期
状态：新增/修订/废止/待验证
影响：对定位、产品、视觉、营销或执行的影响
```

## 更新规则

1. 新材料先登记来源，后写结论。
2. 事实与偏好分开；灵感图不是消费者证据。
3. 冲突并列记录，注明由谁、用什么证据裁决。
4. 新结论替代旧结论时保留旧ID，并写“被何条替代”。
5. 决策记录日期、决策人、选择、备选、理由、代价和复盘日期。
6. 每轮只追加知识库增量，避免整库重写导致历史丢失。

版本使用 `v主版本.次版本-YYYYMMDD`。定位或核心视觉方向改变升主版本；证据、表达或执行细节更新升次版本。
